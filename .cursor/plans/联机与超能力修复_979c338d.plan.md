## 补充扫描新发现（计划外）

### A. 法力双加（同 P0-1 模式）— 真缺陷

[`HealManaSynced`](Common/Net/ServerPlayerNet.cs)：服务端先改 `statMana`，再 `MessageID.ManaEffect`（客户端 `ManaEffect` 会再加法力），再发 `HealMana` 包又加一次。护士投药 [`NurseHealProjectile`](Common/Roles/Nurse/NurseHealProjectile.cs) 走此路径。

修法：去掉广播 `ManaEffect` 作为权威加蓝；拥有者只靠 `HealMana` 包；他端若需蓝字用仅特效路径（或不播）。

### B. SSC 扣款双扣 — 真缺陷

[`TrySpendCopperSynced`](Common/Net/ServerPlayerNet.cs)：服务端 `BuyItem` 后仍发 `SpendCopper`，客户端再 `BuyItem`。在 **SSC** 下服务端背包权威，会扣两次。`!SSC` 时服务端常扣空失败、只扣客户端，故单测难复现。

修法：SSC → 只 `BuyItem` 服务端并镜像相关币槽；`!SSC` → 只发 `SpendCopper`、服务端不 `BuyItem`（或 best-effort 但不向客户端再扣）。

### C. 断线守卫覆盖不全 — 真缺陷（同族）

除 [`NpcAiSpeech.NotifyPlayerLiteral`](Common/Ai/Chat/NpcAiSpeech.cs) 外，下列也直接 `SendChatMessageToClient`、无 `IsConnected`：

- [`NpcFollowNetSystem.NotifyPlayer`](Common/Ai/Follow/NpcFollowNetSystem.cs)
- [`ArmsDealerTempWeaponPower.ReclaimAll`](Common/Superpower/ArmsDealer/ArmsDealerTempWeaponPower.cs)

应统一走带守卫的封装，或各点补同一检查。

### 扫过但未列入本轮

- ExtraAI 多 GlobalNPC（跟随 / 护士投掷 / 树妖光环）在 tML 下按实体拼接，协议自洽；`netAlways` 时带宽偏高，非逻辑错误
- 进服 Dummy 全量快照缺失：可能影响「中途进服不开火」，断线守卫验后再说；新包号用 **29**
- 哥布林附魔依赖 snapshot 的 `selectedItem`：靠 P0-3 Pin 缓解，无独立新洞

## 本轮必修：断线守卫

统一检查后再 `SendChatMessageToClient`：

```csharp
if (playerWhoAmI < 0 || playerWhoAmI >= Main.maxPlayers) return;
Player p = Main.player[playerWhoAmI];
if (p == null || !p.active) return;
if (Main.netMode == NetmodeID.Server
    && (Netplay.Clients[playerWhoAmI] == null || !Netplay.Clients[playerWhoAmI].IsConnected))
    return;
```

无模型提示：仅成功发送后置 `NotifiedNoModel[p]=true`。
